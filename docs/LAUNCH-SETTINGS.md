# 每游戏启动设置与恢复

安装器候选版本：**0.3.0-beta.1**。这是 Manager 的版本，与导入的 NR Core / 插件版本分别记录。公共默认包不包含 NR 成品。

## 玩家流程

游戏详情中分别选择 SR 和 FG 设置。保存只记录下次请求；预览并确认后才应用。游戏运行时可以保存，不能写入配置。只有**从管理器点击启动**时，Steam 和直接 EXE 启动才经过相同的配置预处理；从外部 Steam 客户端启动不经过管理器。

配置写入和回读成功标为“运行待验证”。管理器尚未观测实际渲染输入 R、输出 O、生成帧数或呈现节奏，因此不能把请求值显示为实测值。驱动写入失败且已安全回退时，可以明确选择继续启动；仍有未恢复事务时禁止启动。

## 设置域

| 设置 | 写入位置 | 限制 |
|---|---|---|
| 原生 SR，默认路线 | 当前完整 EXE 的 NVIDIA DRS profile | SR override / quality / ratio / 显式 K、L、M；不写 RR、NR、HDR，FG 值不变 |
| 已安装 OptiScaler 的 SR | 现有 OptiScaler.ini 两个 UpscaleRatio 键 | 可选后端，不作为原生 SR 或 RTX50 FG 前提；75% R/O 转为约 1.33333 的 O/R |
| RTX50 官方 FG | 当前完整 EXE 的四个 FG DRS 键 | 关闭、固定或 Dynamic 是驱动请求；总倍率 N 转为生成帧数 N−1，不依据头文件上限推断游戏支持16X |
| RTX40 社区 MFG | 现有 RTX40MFG-Universal.json control v11 | 跟随游戏、固定、动态；跟随不等于关闭；必须已有可用 Streamline FG，不给无 FG 游戏注入后端 |

RTX40 配置路径遵循固定上游：存在 CET 的 RTX40MFG/init.lua 时只用其目录，否则用 EXE 旁边。自定义环境变量路径不猜测；未知协议、重复 JSON 成员、无法无损保留的数值和超出实际 4096 字节读取上限均拒绝。原 generatedOnlyDebug 保留并提示；存在该标志且需要更改时必须手动预览确认，不从下次启动请求自动激活。

目前检查的是已有配置和已识别 GPU 家族，**尚未认证社区 wrapper 当前会话或证明后端 DLL 已正确加载**。RTX50 的固定 / Dynamic 上限同样需要真实游戏证据。现有 NVIDIA 全局、共享或不能唯一绑定完整 EXE 的 profile 拒绝修改；不会为通过测试清除预设或转写全局配置。

## 激活接口与模块边界

`LaunchSettings` 提供 `save`、`inspect`、`preview`、`apply`、`beforeLaunch`，是主进程使用的配置入口。renderer 只能调用对应命名 IPC，不能传文件路径、任意驱动键或执行脚本。

- `launch-profile-plan.cjs` 保留纯配置编译与 CLI，不接触系统。
- `launch-policy.cjs` 隐藏具体键、协议、文件路径与逐键恢复规则。
- `launch-settings.cjs` 把配置操作接到已有 Engine 的串行化、备份、历史和恢复入口，不另建独立恢复栈。
- `nvapi-profile.cjs` / `native/nvapi-profile.ps1` 隐藏 Windows interop。读取完整受限快照，比较后只修改变化项，一个 DRS session 保存并回读。
- ReShade / carrier 的真实激活与运行保护属于运行时；安装器的检查不能代替它，也不能拦住玩家手动复制 DLL。

## 恢复约束

首次使用设置功能或保存 API 偏好之前备份元数据并升级 state schema 5，旧版本拒绝读取。配置使用 Engine 的 `launch-settings` journal；必须按与 addon 更新相同的逆序恢复。保存下一次请求不制造“已经应用”的收据。

每个驱动键区分显式值、继承值、不存在；显式 0 不等于缺失。恢复继承值时删除本工具覆盖，并接受当前真实继承值，不把旧继承值写成新的显式覆盖。创建的 profile 名称由完整 EXE 路径派生，只在独占、归属明确且无外部显式设置时删除；有外部键则保留 profile，仅恢复本工具覆盖。撤销一次恢复可以重建同一个派生 profile，不能借此创建任意 profile。

配置备份保存原始字节。未发生后续修改时恢复原件；有无关修改时只合并本工具接管的键。已接管键被外部改动、备份损坏、临时文件变化或读回失败时保留记录，不强行覆盖。文件变更和驱动变更未完成时，都能从恢复记录继续。

## API 选择

DXGI 本身不表示 DX11 或 DX12。EXE 只有 DX11 线索时保持待确认；直接导入、入口点和被导入引擎模块的候选集合合并，不能因为先看到 DX11 就跳过 DX12 引擎证据。

玩家选择绑定完整 EXE 路径保存，同路径游戏更新和重新扫描不覆盖选择；换 EXE 不沿用原偏好。静态证据、已加载模块和玩家选择均与真实渲染证据区分。对于《看门狗：军团》，当前回归验证的是 DXGI 待确认→选择 DX12→重新扫描仍保留→合成载荷安装的管理器流程，**没有启动真实游戏**。

## 验证与未完成项

本机 Windows 已通过源代码门禁、185 项测试，以及真实 Electron 的合成目录安装、A/B/A、卸载、撤销和反馈流程。NVAPI 对独立合成 EXE 实际完成 SR 写入、回读、恢复、撤销恢复和最终还原，最终无专属 profile、无待恢复事务。测试 EXE 从未执行，现有游戏和全局 profile 未写入。审查结论和后续任务见 [候选审查记录](REVIEW-0.3-CANDIDATE.md)。

真实游戏 SR R/O、RTX40/50 FG/MFG 效果、长期稳定性均未验收。Own Core 的多 API 配方、按路线 carrier 部署与停用、RenoDX HDR 角色隔离、Vulkan layer 注册及共享引用仍是独立待完成增量，不因本次设置接口通过而标记完成。
