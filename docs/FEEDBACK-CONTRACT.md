# 反馈与诊断契约 v1

本功能只读收集管理器证据，运行时采集仍由独立组件完成。没有私有仓库入口、凭据保存、后台上传或自动创建 Issue。GPU/驱动和截图不自动采集。

## 输出与确认

`public-report.md` 为界面中预览的精确文本，含版本、API、组件摘要、SHA-256、事务与事件码、症状、复现步骤和证据缺口。默认不包含游戏名与 EXE 文件名，用户可以选择公开；绝对路径始终不主动收集进报告。自由文本经过路径、链接、邮箱、已知凭据及账号字段过滤，但不能保证识别所有秘密，导出/复制仍须确认预览。

“复制并打开 GitHub”只把标题放入 Manager 公开 Issue 页网址，报告正文留在本地剪贴板。用户粘贴并点击提交后才创建 Issue。运行时反馈由维护者内部另行分流。

`diagnostic-private.zip` 默认只有同样脱敏的报告、管理器摘要和说明。只有单独确认包含附件后才加入原始 `runtime-feedback.zip`；它可能含路径、账号或截图隐私，**不会被静默改写成所谓已脱敏附件**，也不会自动公开。请自行检查并通过确认的私下渠道发送。

## 输入包

选择本机 ZIP，上限 64 MiB、64 项、单项 16 MiB。仅在内存中读取，不解压至游戏目录、不执行、不渲染截图。安全相对路径允许子目录，但不允许绝对路径、父目录、链接、重名、CRC 或哈希异常。当前不接收转储、源码、PDB、EXE、DLL 或 addon。

标准包根目录为 `feedback-manifest.json`，必填：

- `schemaVersion: 1`
- `producerId`: nr-before-sr / dlss5-manager / reshade
- `producerVersion`、`createdAt`、`gameExeName`（只要文件名）
- 可选 `api`: DX11 / DX12 / Vulkan / OpenGL
- `files[]`: path、role（log/screenshot/summary/other）、sha256；可选 sensitivity（public/private/sensitive）

文件列表不包含清单自身，必须覆盖全部普通文件；目录项不计入。每个哈希匹配后显示“清单与哈希一致”，不宣称发布者已认证。即使 sensitivity 写成 public，原附件仍不会进入公开报告。

没有 manifest 的旧 ZIP 可作为“旧格式、非结构化附件”保留，仍做 ZIP 结构和体积检查。存在 manifest 但版本未知、内容损坏或哈希失败时拒绝，不能降级成旧格式逃过校验。

包内 API、EXE 和组件版本与所选目标不一致时显示证据缺口；没有运行时附件的画面/不生效/崩溃报告显示“证据不足”。这些提示不是禁止用户反馈，也不是已经判明 Bug 根因。

## 安全边界

选择、生成、复制、打开页面及导出均通过主进程固定 IPC 方法。草稿使用一次生成的服务器端快照与有效期，不能由前端改写导出正文或任意目标 URL。报告禁止保存到已知游戏目录和管理器状态目录。原始附件不得进入公开报告；私有包仍须单独确认。

## 多包发送入口（0.2.0-beta.3 候选）

Manager 接受本次选择的一个核心 ZIP，或最多两个 ZIP 作为一个发送集合；未识别的运行时格式仍是不透明附件，而不是 Manager 清单格式的变体。两个附件仅因同时选择不会被标记为配对成功。已有严格清单损坏仍拒绝，不能降级为不透明包。

玩家可主动粘贴组件完成采集后的摘要；先脱敏、再预览，标记为用户提供，不能替代附件或当前运行证据。更换反馈游戏清空旧摘要及旧附件；取消文件选择保留旧集合，导入失败清空旧集合和预览，防止旧数据冒充新数据。

本地私下导出：public-report.md、manager-summary.json、attachments.json、READ-ME.txt，以及明确勾选才加入的原始 ZIP。附件重验预览时的大小和哈希，按编号保留原字节，不将绝对路径或原始日志放进公开报告，不自动上传，不执行组件的采集器或脚本。

限制：每个 ZIP 64 MiB、单个解压文件 16 MiB、最多 64 个条目，总计最多两个 ZIP。大图像包需单独发送；本轮没有放开为无限制解压，也没有证明真实组件每一种 F7/F8 包都满足这些约束。精确 session/binary/core-image 关联适配留在 #14 验收。
